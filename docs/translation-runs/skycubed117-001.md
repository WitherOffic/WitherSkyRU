## Причина и реализация

В проверенном SkyBlock API4.2.41 событиеPre публикуется из Fabric ALLOW_GAME до помещения сообщения в обычный чат. SkyCubed распознаёт NPC/ответы, сохраняет исходные компоненты и может отменить чат. WitherSkyRU переводит обычный чат позже, в display queue; этот hook не получает отменённую реплику. Разделённые SkyCubed поля также теряют полный префикс, необходимый существующим NPC-правилам.

Исследованы фактический JAR SkyCubed1.10.0 для26.2, его вложенный API, подписи/вызовы байткода и [первичный исходник DialogueOverlay.kt](https://github.com/meowdding/SkyCubed/blob/54937a790ae1ed4f8b99271e3e930f56cf0acd0c/src/main/kotlin/tech/thatgravyboat/skycubed/features/overlays/dialogue/DialogueOverlay.kt). Адаптер содержит три точечные инъекции:

1. После NPC-regex переводит копию тела перед нативной вставкой пары в очередь. Имя для поиска NPC/портрета остаётся исходным.
2. После извлечения группы ответов переводит подписи до создания нативных Command/ClickPayload. Сохраняются команды, Custom ID/payload и цифровые клавиши.
3. Переводит поддержанное словарём имя только как аргумент построения display, после поиска сущности.

Для движка восстанавливается временная NPC/option-оболочка. Полные известные предложения и смешанные компонентные фрагменты используют текущие провайдеры; новых переводов конкретных NPC в адаптере нет. Неизвестный текст остаётся исходным. Цвета, форматирование, click/hover/insertion передаются из актуальных компонентов; оригинальное событие не мутируется. Повторной вставки сообщений или нового render hook нет.

Mixin активируется только для проверенных версий и SHA классов SkyCubed/API. При отсутствии либо обновлении бинарников он пропускается. Строковая цель/@Pseudo исключают обязательную загрузку чужих классов; require1 не ослаблен. Подробности и хеши — [карта интеграции](../SKYCUBED_DIALOGUE_26_2.md).

Клиенты запускались в новых изолированных папках, с копиями публичных модов и тестовым офлайн-аккаунтом; рабочая сборка/настройки/аккаунты не изменялись. В настоящем клиенте вызывался нативный обработчик SkyCubed на публичных контролируемых примерах, без подключения к Hypixel. Этот тест доказывает применение Mixin и сохранение данных взаимодействия, но не визуальную корректность всех окон или принятие ответа реальным сервером.

Collector наблюдает только окончательный результат overlay, отдельно от обычного чата. Его согласие, границы источника, фильтры и ограниченная дедупликация сохранены. Статусы проверены тестовым перехватом с временным loopback-владельцем; без доверенного мира Hypixel отправляемых наблюдений0. Производственный сервер, PostgreSQL, HTTP API и синхронизация не затрагивались. Реальная отправка остаётся ручной проверкой.

При подготовке исправлены два дефекта самой проверки: Mixin переименовывает handler-методы, поэтому smoke ищет их по вхождению, а не началу имени; override-фикстура теперь создаёт dictionary и ChatNotificationTranslator с одним набором данных, как настоящий startup. Изначальный native smoke с ошибкой имени сохранён как непринятый результат в ignored build; последующие проверки выполнены заново. Контейнер кандидата отличается от финального JAR только стандартным Loom manifest; классы/ресурсы идентичны. Финальный JAR отдельно запущен в обоих режимах.
