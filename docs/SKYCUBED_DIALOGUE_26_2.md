# WitherSkyRU — SkyCubed NPC Dialogue Overlay

Адаптер встроен в единый WitherSkyRU для Minecraft26.2/Fabric/Java25. Отдельный мод, словарь или ручное отключение NPC Dialogue Overlay не нужны. Действуют обычные настройки WitherSkyRU, включая переключатель перевода NPC и пользовательские overrides.

## Причина и проверенная версия

В SkyCubed1.10.0 серверная реплика попадает в `ChatReceivedEvent.Pre`, разбирается на имя/текст либо варианты ответов и может отменяться до обычного чата. WitherSkyRU переводит обычный чат позднее, в `ChatComponent.addMessageToDisplayQueue`. Отменённая реплика туда не доходит; сохранённые SkyCubed компоненты также лишены полного NPC-префикса, необходимого существующим закрытым правилам.

Проверены **SkyCubed1.10.0 для26.2** и вложенный **SkyBlock API4.2.41** из локального игрового набора. СобытиеPre в этом API публикуется из Fabric `ALLOW_GAME`, а не из канала сообщений игроков. Порядок и подписи вызовов сверены по фактическому байткоду; имя JAR не использовалось как единственное доказательство версии.

Первичный исходник: [DialogueOverlay.kt, закреплённый коммит54937a7](https://github.com/meowdding/SkyCubed/blob/54937a790ae1ed4f8b99271e3e930f56cf0acd0c/src/main/kotlin/tech/thatgravyboat/skycubed/features/overlays/dialogue/DialogueOverlay.kt). Он сверён с рабочим файломmaster и исследованным байткодом. Решающим для подключения остаётся локальный бинарник, а не меняющаяся веткаmaster.

CompatibilityMixinPlugin допускает адаптер только при совпадении обеих версий и двух хешей классов. Отсутствующий, обновлённый или изменённый бинарник отключает только этот адаптер до новой проверки; классы SkyCubed из общего кода WitherSkyRU не загружаются. `@Pseudo`, строковая цель и точные `require=1` сохраняют обычную работу без SkyCubed. Версии не расширять предположительно и `require` не ослаблять.

## Три точки интеграции

1. После успешного NPC-regex, перед созданием нативной пары в очереди SkyCubed, меняется только отображаемая копия текста. Исходное имя сохраняется для `DialogueNpcs` и `DialogueEntities`. Для существующего движка временно восстанавливается исходный NPC-префикс; используется тот же порядок провайдеров, что в обычном чате.
2. После извлечения группы ответов, до создания `Option.Command`/`Option.ClickPayload`, переводятся видимые подписи. Сначала используются существующие семейства ответов целиком, затем отдельные известные подписи. Команды, ID/payload, клавиши и логика отправки SkyCubed остаются нативными. В адаптере нет переводов конкретных NPC.
3. В `createMainDisplay` переводится только аргумент отображения имени, если оно поддерживается текущим словарём. Ключ поиска портрета и очередь с исходным именем не меняются.

Полные известные NPC-предложения внутри смешанного дерева повторно проходят существующий NPC-движок; прочие поддержанные фрагменты — существующие компонентные правила. Частично русский текст сохраняется. Границы слов и произвольные подстроки одного неизвестного литерала не угадываются. Неизвестные, слишком длинные или непрозрачные компоненты остаются исходными. Текущие стили переносятся свежими, вместе с click/hover/insertion и `ClickEvent.Custom`; исходный компонент события не мутируется.

Работа выполняется при обработке сообщения/создании подписи, без нового обработчика кадра, повторной вставки в очередь, кэша живых компонентов или сетевого переводчика. Уже переведённые компоненты идемпотентны. Точное влияние на FPS/frametime/память не измерялось.

## Collector и границы источника

Обычный чат сохраняет прежний маршрут и контекст `SERVER_NPC`. Overlay наблюдается один раз после окончательного перевода и fallback: `NPC_DIALOGUE / SKYCUBED_NPC_OVERLAY`. Для ответов сохраняется реально видимая группа, без выдуманного NPC: `GUI_TEXT / SKYCUBED_NPC_OPTIONS`.

Совпадение исходного/итогового текста даётMISSING, изменённый результат —TRANSLATED; существующая диагностическая классификация Collector на рабочем потоке сохраняется. Промежуточный неудачный lookup не создаёт отдельныйMISSING для успешно переведённого overlay. Уже русский текст без английского содержимого не считается пропуском из-за латинского имени NPC. Сохраняются согласие, отдельные категории, проверка Hypixel/SkyBlock, фильтры приватных данных и ограниченная дедупликация. Игроки/личный чат/ввод не направляются в адаптер: его точки находятся после серверных NPC/option-regex проверенной API-версии.

Сервер, PostgreSQL, HTTP API и синхронизация не менялись. Автотесты не отправляют записи на рабочий сервер. Проверка статусов намерения использует тестовый перехват и временного владельца с адресомloopback, без мира/Hypixel; реальный фильтр не допускает постановку этих данных в отправляемую очередь. Это не проверка живой отправки.

## Проверки в Minecraft пользователем

1. Установить выданный единый JAR вместо прежнего WitherSkyRU, оставить проверенный SkyCubed и включённый NPC Dialogue Overlay. Не держать две версии WitherSkyRU одновременно.
2. Открыть диалог David Hunterborough о Kysha: проверить русский текст, цвета ключевых слов, переносы, размер окна и портрет NPC.
3. Получить ответAnything else?: проверить русскую подпись и реальный выбор мышью и клавишей1. Аналогично проверить вариант с `ClickEvent.Custom`: тот же ответ должен приниматься сервером.
4. Отключить overlay и проверить обычный чат; затем выключить перевод NPC и убедиться, что соблюдается настройка. Уже русские фрагменты не должны портиться или дублироваться.
5. При осознанно разрешённом Collector проверить реальный известный перевод и реальный новый пропуск в административной панели: успешный overlay не должен получать искусственныйMISSING. Отказ/отзыв согласия должен прекращать сбор. Не отправлять синтетические строки на рабочий сервер.

До этого WSRU-0003 имеет статус «Ожидает проверки в игре». Изолированный запуск настоящего клиента и вызов нативного обработчика проверяют загрузку/инъекции/данные, но не заменяют живое общение с NPC, ввод ответа на сервере или визуальную оценку размещения текста.
