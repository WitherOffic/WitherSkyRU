# Проверка нагрузки и оптимизация WitherSkyRU 0.15.62-dev

14 октября 2026. Оптимизация без добавления новых переводов и без
отключения перевода ради результата. Фактический игровой FPS пока не
измерен: запущенная игра не обнаружена. Установленный модпак не изменён.

## Что проверено на компьютере

В профиле PrismLauncher «Skypixel (for Hypixel Skyblock)» установлен
**0.15.53-dev** — проверена версия внутри fabric.mod.json, не только имя
файла. SHA256 установленного файла:
6C67C5AD2859F646E4439EB86FC8E7491F07964F823414C8328D90FD3418E489.
Подготовленные 0.15.61 и 0.15.62 не устанавливались автоматически.

Сравнение одного скриншота ночью и другого днём, особенно с шейдерами,
не позволяет отделить вклад мода от изменения сцены. Нельзя честно
обещать ровно тот же FPS по одному замеру или по тесту текстовых API.

## Найденные причины лишней работы

1. В обработке соседних строк подсказки одни и те же выражения заново
   компилировались для очередной строки. Подготовлены семь неизменяемых
   шаблонов, а дешёвая проверка соседнего текста выполняется первой.
2. Пятнадцать неизменяемых описаний создавались заново; сравнение с ними
   выделяло вспомогательные подсписки. Описания подготовлены один раз,
   строки сравниваются по индексам с ранним отказом.
3. Даже при отсутствии пользовательских замен создавался поток ключей
   и выполнялось преобразование регистра. Пустой набор теперь сразу
   отклоняется; непустой проверяется обычным циклом с прежней семантикой.
4. Простые числа, проценты, разделители и уже окончательные подписи
   проходили лишний путь анализа. Их пропуск ограничен доказанными
   неизменяемыми формами, а не предположением «весь русский текст готов».
   Числовые значения больше не заполняют словарные кэши без необходимости.
5. Для одноцветной строки создавались лишние списки стилевых диапазонов.
   Список выделяется только при необходимости; текущие цвета и действия
   всё равно считываются заново. Результаты Component/Style не кэшируются.
6. Анализ стека сохраняет прежние границы 48/64 кадра вызова, но без
   дополнительной стадии потоковой обработки.
7. В очереди сообщений удалены две повторные внешние проверки: внутренний
   переводчик уже проверяет те же полные ключи и семантические overrides.
   Три формы запросов и декорация головы получили заранее подготовленные
   выражения; счётчики используют уже существующий разборщик.

Дополнительная проверка выявила регрессию в Received-датах: анализ
защищённого ввода вызывался из лишней внутренней обёртки. Проверка
возвращена в публичную точку входа; её условия и ранний числовой отказ
сохранены. Прототип сравнивается отдельно от прежнего неподтверждённого
JAR, результаты которого не выдаются за окончательную сборку.

Подозрение на лишний переход между двумя низкоуровневыми обработчиками
проверено по реальному байткоду Minecraft 26.1.2. Предложенный общий флаг
для такого перехода не дал подтверждённого выигрыша и **не включён** в
итоговый JAR. Нативные обработчики и функции подгонки текста не отключены.

## Исправление накопления диагностических строк

Прежний код сначала добавлял неизвестную строку в множество и только
потом проверял размер. После порога 15 000 запись на диск прекращалась,
но множество продолжало удерживать новые строки в памяти.

Теперь лимит проверяется до добавления под общей блокировкой. Максимум
15 000 уникальных записей, очередь 256 строк, не более одного ожидающего
задания записи. Фоновый поток пишет пакетами до 64 строк вместо открытия
файла для каждой отдельной строки. При переполнении диагностика работает
по принципу best effort: лишние неизвестные строки могут не попасть в
журнал. Это **не пропуск перевода** и не изменение сообщений сервера.

Тест искусственно блокирует диск, подаёт 16 000 событий и проверяет
пределы, отсутствие ожидания свободного места в очереди, порядок и
однократность принятых строк. Дальнейшие записи после лимита не приводят
к росту множества. Переключатели записи и тихий поиск сохранены.

## Сравнение нагрузки

Четыре последовательных запуска: 61→62, 62→61, 53→62 и 62→53. В каждом
51 сценарий, 20 000 пакетов прогрева и четыре раунда по 4 000 пакетов,
фиксированная куча 256 МБ. Все раунды сохранены. Перед замером закончены
собственные компиляции/проверки. JSON подтверждают загрузку нужного JAR.
Единица — десять синтетических строк; это не полный кадр Minecraft.

## Как подтвердить результат по FPS

Нужен отдельный контролируемый тест пользователем: тот же профиль,
настройки, камера, место, освещение и шейдеры; дождаться загрузки чанков
и прогрева. Сравнить несколько отрезков с модом и без него, желательно
в разных порядках. Записать не только средний FPS, но и время кадра /
редкие просадки. Изменение времени суток или количества объектов делает
сравнение неоднозначным. В один запуск должна входить только одна версия
WitherSkyRU; старые файлы нужно сохранить вне активной папки mods.

Если разница сохранится, следующий шаг — профиль именно запущенной игры,
с привязкой горячих методов к просадкам кадра. Для этого сейчас нет
измеренного игрового сеанса. Игра не запускалась и модпак не менялся.
