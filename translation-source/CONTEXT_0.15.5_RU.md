# 0.15.5-dev — оригинальное название по Shift и исправление поиска/ввода

Дата: 2026-10-11. Пользователь просит оригинальное название при удержании Shift
в инвентаре; затем сообщил, что русский поиск RRV всё ещё пустой, а набранный
английский текст в чате/поиске отображается переведённым. Запросы объединены.
Последний локальный latest.log и mods подтверждали WitherSkyRU 0.15.3-dev,
RRV 8.10.9+26.1.2. Установка более новых Desktop JAR ранее НЕ выполнялась.

## Shift

OriginalItemTitle.held() проверяет оба Shift через InputConstants.isKeyDown
и контейнерный экран, плюс active() мода. TooltipTranslation сохраняет первую
строку list-tooltip в оригинале и переводит остальные. Marker OriginalSequence
предотвращает повторный перевод в overload и display-хуках; unwrap при следующем
вызове без Shift возвращает обычный путь. TooltipTextFit также сохраняет
исходный заголовок при прямом входе в низкоуровневую подготовку.

ContainerScreenAccessor читает hoveredSlot. Для прямых String/Component/sequence
вызовов, минующих список, сохраняется точное имя предмета в наведённом слоте.
Никакого обратного перевода русского текста, угадывания английских имён,
мутации ItemStack, сетевых пакетов или перехвата действий Shift.
Нестандартные tooltip со своей геометрией/изменённым заранее названием,
без первой строки-title или без наведённого контейнерного слота не гарантированы.

## Поля ввода

Прежние display-хуки могли показывать русский текст вместо введённого английского,
хотя getValue/строка отправки не менялись. UserInputText проверяет render-stack
EditBox/MultiLineEditBox; text/component/sequence возвращают источник без перевода.
Это защита отображения, не замена getValue, клавиатурного ввода или команды.
RRV SearchBar наследует EditBox. Полученный чат и обычные надписи не исключены.
Произвольные полностью собственные поля сторонних модов требуют отдельного анализа.

## RRV: настоящий пропущенный путь

Байткод ItemViewOverlay.tooltipMatch добавляет getHoverName/getItemName в список
подсказок и вызывает ItemFilters.getListMatch. Он использует getMatch для каждого
Component. Предыдущий redirect только defaultFilter не покрывал этот путь.
Новый HEAD inject в getMatch добавляет совпадение по русскому alias для кириллических
запросов. Английские запросы проходят исходный код. Явные ID/теги/namespace не меняются.
Текст запроса никогда не заменяется; aliases локальные и из тихого dictionary-пути.
Version guard остаётся только 8.10.9+26.1.2.

Теперь проверен не только факт трансформации, но и настоящий getListMatch
через Knot classloader: кирка, кир, кирка алмазная => 2; Pickaxe => 2,
lowercase английский fixture тоже найден. Неизвестный запрос даёт 0,
исходный Component по-прежнему Diamond Pickaxe. У самого RRV native matching
literal-компонентов регистрозависимо; мы не меняли это поведение для английского.
